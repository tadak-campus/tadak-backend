# 타닥캠퍼스 FastAPI 백엔드 MVP

PDF 학습자료 기반 타이핑 연습과 포인트 상점 기능을 위한 FastAPI MVP입니다.

## 실행

```bash
uvicorn app.main:app --reload
```

서버 실행 후 Swagger 문서는 아래에서 확인할 수 있습니다.

```text
http://127.0.0.1:8000/docs
```

기본 DB는 프로젝트 루트의 `tadak.db` SQLite 파일입니다. 다른 DB 파일을 쓰려면 `DATABASE_URL`을 지정합니다.

```bash
DATABASE_URL=sqlite:///./local.db uvicorn app.main:app --reload
```

## PDF 처리 방식에 대해

첫번째는 PDF에서 텍스트를 추출해 정리본을 LLM에 넘기는 방법이다. pypdf 같은 라이브러리도 많고 무엇보다 비용 최적화가 가능할 것이다. 문장 추출이 어디에서 됐는지 트래킹도 가능할 것이다.
다만 PDF의 레이아웃 정보가 붕괴하게 된다. 각기 다른 수업자료 형식에 따라(텍스트가 많은 or 도식이 많은) 문장 추출 퀄리티가 천차만별 달라질 것이다. 
결국 MVP든 상용이든 제품화 수준에 상관없이 좋지 못한 방법이라 생각된다. (물론 텍스트화 레이어에 대해 돌을 극한으로 깎아내면? 라는 생각도 들지만 이 수단의 상한엔 한계가 있을 것 같다)

타닥에서 채택한 두번째 방식은 단순하게 LLM API에 파일을 통쨰로 첨부하는 것이다. 각 API의 지원 여부를 보아야 하겠지만 PDF 포멧은 상용 LLM API는 대부분 지원한다고 판단했으며 실제로 그러하다. (PPTX는 안되는 것도 있긴 해 지원 포멧에서 제외함)
우리가 사용한 범용 Gemini API는 최대 1000페이지 이내 or 50MB 용량 이하의 pdf 파일을 지원하며 대게의 대학생 수업자료는 이 조건에 만족한다고 판단했다. 
그래서 대용량 파일용 API를 선택하진 않았다.

추후 문제가 발생할 수 있을 법한 지점은 PDF 파일을 재사용하는 기능이 도입되는 경우라 생각된다. 이를테면 수업자료 기반 타이핑뿐 아니라 자료 기반 퀴즈를 만들거나 복습 카드를 만드는 등의 경우이다.
큰 pdf가 모델에 올라와 지속적으로 활용되는 경우 컨텍스트 비용 문제가 발생해 최적화가 반드시 필요한 지점이 있긴 할것이다.
아래와 같은 방법들을 생각해볼 수 있을 것 같다.

- batch api로 타이핑 문장, 퀴즈 등의 작업을 한번에 하기
- 컨텍스트 캐싱 기능 활용 극대화(캐싱을 유도하는 시스템 프롬프트 등)
